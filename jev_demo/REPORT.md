# Jev 用于 RMUC 决策的评估报告

日期 2026-09-21 · 评估对象 `jev-1.13.0`（TypeSafe AI，2026-09-15 发布）· 数据 RMUC 2026 赛区数据集
· 对照模型 `rm_runs/infantry_iql_tactical/best.pt`（Navigator 战队 / BNBU）

---

## 摘要

在 61 场验证赛的 99,570 条转移上做了三方对比（人类操作手的实际动作 / 你们的 infantry IQL / Jev），
外加 613 场全量的胜负判断实验。总共 5,676 次 Jev 调用，花费约 2.0 美元。

**逐项裁定：**

| 决策 | 最优 | 次优 | Jev 位置 |
|---|---|---|---|
| 胜负判断 | 5 特征逻辑回归 AUC **0.864** | 单特征 team_hp_diff 0.797 | **0.789**，excess −0.075 |
| 目标选择 | 闭式几何规则 **1.000** | IQL 0.730 | **0.212**，低于"最近活敌"0.264 |
| 火力门 | **Jev** AUC **0.769** / F1 0.525 | IQL AUC 0.611 / F1 0.381 | **赢** |
| 导航子目标 | "原地不动" **1.54 m** | IQL 1.91 m | 1.94 m，**三者都不如不动** |

**结论三句话：**

1. **Jev 不能做 RM 的战术决策层。** 目标选择上它只有 0.212，比"打最近的活敌"这条一行规则（0.264）还差，
   且差距在统计上显著（95% CI [0.189, 0.235] 对 0.264）。胜负判断上它跑不过一个 5 特征逻辑回归，
   连校准（ECE 0.062 vs 0.017）都输。**它在这个域里没有超出表面统计量的知识。**
2. **但它的火力门明确比你们训出来的 head 好**，而且赢在校准：预测均值 0.2344 对真实正类率 0.2208，
   AUC 0.769 对 IQL 的 0.611。这是唯一有实证支持的接入点。
3. **评估过程中发现你们数据集有两个标签缺陷，其中一个直接影响开源项目的 headline 指标**，
   见 §3.1。修掉它们比接入任何外部模型都更要紧。

## 1. 评估设置

### 1.1 三个决策者

| | 来源 | 信息 |
|---|---|---|
| 人类操作手 | 数据集标签（步兵3/步兵4 是人操作的） | 第一视角图传 + 小地图 |
| 你们的 IQL | `infantry_iql_tactical/best.pt`，obs 161 / act 10 | 完整裁判系统状态（`vis_radius=0`） |
| Jev | `jev-1.13.0`，Choice/Noul 原语 | 与 IQL 逐项对齐的同一份信息 |

### 1.2 数据与管线自检

用 `rm_rl` 包本身重建 obs 和标签，没有重新实现任何特征，所以与训练时逐位一致。验证集按
`build_dataset.py` 的确定性划分复现（seed 0、`val_frac` 0.1）：**61 场、99,570 条转移、87,577 条 valid、
44,837 条带具体目标**。

自检：IQL 在这批数据上的 `target_top1_named` = **0.7455449**，与 README 的 0.7455 一致到小数第四位。
管线可信。

### 1.3 为公平性做的处理

- **同信息**：Jev 的 state 逐项对齐 obs 的内容（6 固定队伍槽含 ego 自身、6 敌人槽含 `position_known`
  与 vis_map 的 engagement prior、建筑、经济、leak-safe 对手强度先验），并同样镜像到红方规范帧。
- **完整规则 briefing**：把 V2.1.0 规则手册的胜负链、前哨站→基地无敌、易伤数值、热量锁定、
  增益点、经济、复活、兵种特性写进 `state`，外加一份字段语义词典。
  这是必需的：先前只给 70 token 摘要时，同一个状态下 Jev 的导航结论会 180° 反转（见 `jev_ab.py`）。
- **两个泄漏条件**：给 / 不给 `turret_bearing_deg`，用来判断分数里有多少来自 §3.1 的标签泄漏。
- **火力门问题严格对齐标签语义**：标签是"刚结束的这一秒是否出弹"，所以问题也问同一件事（回溯），
  否则是在比两个不同的量。

## 2. 实验一：胜负判断（613 场 × 3 个时刻）

问 Jev 一个 Noul：「红方会赢这一局吗」，给完整裁判系统队级状态。1,838 个可用状态，红方胜率 0.5267，
0 次失败，3,339 token/状态，128 秒跑完（14.3 次/秒）。

基线是同一批状态上的 5 特征逻辑回归（前哨站 HP 差、基地 HP 差、队伍 HP 和差、金币差、存活数差），
**按比赛分折做 5 折交叉验证**，确保同一场的 3 个时刻不跨折泄漏。

| | AUC | Brier | ECE |
|---|---|---|---|
| 逻辑回归（5 特征, CV） | **0.8642** | **0.1501** | **0.0168** |
| Jev | 0.7890 | 0.1910 | 0.0620 |
| 单特征 team_hp_diff | 0.7972 | — | — |
| 单特征 outpost_diff | 0.7826 | — | — |
| 恒预测基础率 | 0.5 | 0.2493 | — |

**excess AUC：相对逻辑回归 −0.0751，相对最强单特征 −0.0081。**

分时刻看，差距随比赛进行单调拉大：

| 时刻 | Jev AUC | 逻辑回归 AUC | 差 |
|---|---|---|---|
| t=100s | 0.7491 | 0.7948 | −0.046 |
| t=200s | 0.7990 | 0.8549 | −0.056 |
| t=300s | 0.8280 | 0.9257 | **−0.098** |

**解读。** Jev 比"什么都不知道"好得多（Brier 0.191 对基础率 0.249），所以它确实在读状态；
但它读出来的东西不超过几个 HP 差值的线性组合，而且越到后期越落后——后期局势由累积的 HP/前哨站差
决定，这正是线性模型最擅长而 Jev 最容易过度保守的地方（它的均值 0.491，81 个不同取值，
明显把概率往中间收）。

**这一项也否掉了"RLCD 校准是优势"的期望**：一个用对数损失拟合的逻辑回归天生就是校准的，
ECE 0.0168 对 Jev 的 0.0620，好了近 4 倍。校准优势只在没有可训练基线的场合才值钱。

## 3. 实验二：战术决策三方对比

Jev 采样 1,200 个 `valid & named` 状态 × 2 个条件 = 2,400 次调用，158 秒（15.2 次/秒），
8,683 token/状态，0 次失败。IQL / oracle / 启发式基线**在完全相同的 1,200 行上**重算。

### 3.1 必须先说的两个标签缺陷

**缺陷一：目标标签是 obs 的闭式确定函数（泄漏）。**
`build_obs` 第 10、11 列是 `sin(yaw)`、`cos(yaw)`（[features.py:271](../rm_rl/data/features.py#L271)），
敌人相对位置也在 obs 里；而 `target_soft` 就是用同一时刻的 `yaw` 加敌人相对位置算出来的，
且 `build_action_raw` 取 `target_soft[:-1]`，与 `obs[:-1]` **同索引同时刻**
（[features.py:451](../rm_rl/data/features.py#L451)）。

我实现了这条三行几何规则作为 oracle，它在验证集上的 `target_top1_named` = **1.000**。

后果有三层：

1. `target_top1_named` 衡量的是"能否从观测反解出标签函数"，**不是战术质量**。
2. 你们的 IQL 拿到 0.7455，而一条三行规则拿到 1.000 —— 在这个指标上模型**比规则差**。
   所以 0.7455 不适合单独作为开源项目的 headline claim，至少必须与 oracle=1.000 并列报告。
3. 任何不做这条几何计算的决策者（比如 Jev）在这个指标上会被系统性压低，
   哪怕它的战术判断本身没问题。这也是下面要跑"不给枪口朝向"条件的原因。

**还有一层更根本的问题**：枪口朝向在真实机器人上是自瞄以 100+ Hz 产出的，不是操作手的战术选择
（这正是你们 `action_spec.py` 自己写明的理由）。所以"与人类一致"在这个 head 上
**大部分是在和自瞄一致**，而不是和人的决策一致。

**缺陷二：火力门与导航的标签时间方向相反。**
`fire_gate[i] = 累计17mm发弹[i] − [i−1] > 0`，描述的是**刚结束的那一秒**；
而导航通道用 `x[i+goal_horizon] − x[i]`，描述的是**未来 5 秒**。
同一个动作向量里两个 head 的时间锚点差一秒且方向相反，这让火力门实际上是回溯任务而非决策任务，
也让联合损失在语义上不自洽。

### 3.2 目标选择（7 类，1,200 行匹配子样本）

| 决策者 | target_top1_named | 说明 |
|---|---|---|
| 闭式几何 oracle | **1.000** | 三行规则，泄漏上界 |
| 你们的 IQL | 0.730 | 全量 87,577 行上是 0.7455 ± 0.004 |
| 最近的活敌（启发式） | 0.264 | 无泄漏参照 |
| Jev（给枪口朝向） | **0.212** ± 0.023 | mean conf 0.616 |
| Jev（不给枪口朝向） | **0.197** ± 0.023 | mean conf 0.631 |
| 多数类 | 0.190 | 全量口径 |
| 随机 6 选 1 | 0.167 | |

**Jev 显著差于"打最近的活敌"**（CI 上界 0.235 < 0.264），只比随机好约 4.5 个点。

**一个干净的负面证据**：给不给枪口朝向，Jev 只差 1.5 个点，两个 CI 大幅重叠——**它完全没利用那个泄漏**。
所以 0.212 就是它真实的"战术目标选择与人类枪口指向的一致度"，这个数很弱。
反过来说，IQL 的 0.730 里有多少是几何反解、多少是战术，用现有标签无法分离。

### 3.3 火力门 —— 唯一 Jev 赢的一项

正类率 0.2208（该子样本）。

| 决策者 | AUC | F1@0.5 | 最优阈值 F1 | 预测均值 |
|---|---|---|---|---|
| **Jev（给枪口朝向）** | **0.7695** | 0.000 | **0.525** @0.23 | 0.2344 |
| **Jev（不给枪口朝向）** | **0.7671** | 0.000 | **0.522** @0.26 | 0.2396 |
| 你们的 IQL | 0.6108 | 0.381 | 0.381 @0.00 | — |

**Jev 明确更好，而且赢在校准。** 预测均值 0.2344 对真实正类率 0.2208，只差 1.4 个点——
聚合层面几乎精确校准。`F1@0.5 = 0` 完全是阈值假象：22% 的正类率下 0.5 是错的切点，
按最优阈值 0.23 切，F1 = 0.525，比 IQL 的 0.381 高 14 个点；AUC 0.769 对 0.611 更是说明排序质量的差距。

IQL 这一头的最优阈值是 **0.00**、且 F1@0.5 与 F1@0 完全相同，说明它的原始输出已经饱和成两簇，
几乎没有可用的置信度梯度——这正是 RLCD 想解决的问题，也是这一项 Jev 能赢的原因。

并且**这个优势与泄漏无关**：给不给枪口朝向，AUC 都是 0.767–0.769。

注意这一项受 §3.1 缺陷二影响：标签描述的是刚过去那一秒，所以严格说这里测的是"回溯准确度"。
要当真正的决策门用，得先把标签对齐到未来一秒再重测。

### 3.4 导航子目标

误差 = 预测子目标偏移与人类实际 5 秒位移之间的欧氏距离（米）。

| 决策者 | 平均误差 | 中位误差 |
|---|---|---|
| **"原地不动"（恒零基线）** | **1.542 m** | — |
| 你们的 IQL | 1.907 m | — |
| Jev（给枪口朝向） | 1.941 m | 0.943 m |
| Jev（不给枪口朝向） | 1.982 m | 0.957 m |

**三个决策者全部不如"不动"。** 根因是人类步兵在 5 秒尺度上的实际位移均值只有 1.54 米——
1 Hz 采样下这个 head 的信噪比太低，能学的东西本来就少。Jev 有 68.6% 的状态选了 `stay`，
仍然更差，因为剩下那三成它动错了方向。

这一项和你们此前记录的 nav 模式崩溃是同一个问题，并且**加规则 briefing 救不了**：
缺的不是规则而是几何——障碍图、视线、增益点坐标，这三样数据集里都没有。

## 4. 谁更优

**逐项有答案的部分**（见摘要表）：胜负判断逻辑回归赢；目标选择闭式规则赢、Jev 垫底；
火力门 Jev 赢；导航谁都没赢过"不动"。

**"模型 vs 人类操作手谁打得更好"这个问题，本次评估答不了，而且不是样本量的问题。** 三条理由：

1. **人类不是被比较的一方，而是标准答案。** 所有指标测的都是"与人类实际动作的一致度"。
   一致度高说明模仿得像，不说明打得好；一致度低也可能是模型选了更好的动作
   （先前单点样例里 Jev 选打 3.2 m 外 20 HP 的英雄、人类打 7.3 m 外 100 HP 的步兵，
   就很可能是 Jev 更对）。
2. **信息不对等。** IQL 与 Jev 拿的都是完整裁判系统状态（16 个实体的精确 HP 与坐标），
   人类操作手只有第一视角图传加小地图。这个对比对模型单方面有利。
3. **这正是你们已经撞过的那面墙。** FQE 的 Δ 基本是估计器偏差（BC 明明在模仿行为策略、
   Δ 却是 −8.92），`win_alignment.py` 的 +0.0265 里 +0.0260 被常量策略解释掉。
   反事实问题——"如果当时打的是英雄会怎样"——需要闭环仿真，任何判别式模型都回答不了。

## 5. 部署可行性（不只是延迟问题）

| 约束 | 实测 / 依据 | 判定 |
|---|---|---|
| 赛场网络 | 规则手册 V2.1.0：R3 禁止自行架设无线设备；R31 禁止操作间用自带电脑（自定义客户端除外）；R33 比赛中不可与操作间外通信；唯一认可的场外算力是**有线** RJ45 接入赛事引擎服务器 | **不通过** |
| 微调 | 官方文档：不提供 fine-tune / LoRA，同一套权重服务所有账号 | 90 万条数据用不上 |
| 私有化部署 | 只有 `api.typesafe.ai` 托管端点，服务在美西 | 不可用 |
| 延迟 | 单线程实测：4 问题 / 6,375 tok / 113 选项 = **2,539 ms、2,676 ms**；1 问题 / 1,499 tok = 659 ms、693 ms。官方标称 70–500 ms | 超上限 5 倍 |
| 吞吐 | 14 线程实测 **14–15 次/秒**（限流 1,200 RPM / 250k tok/s） | 离线批处理够用 |
| 成本 | 本次全部实验 5,676 次调用约 **2.0 美元** | 不是瓶颈 |

延迟和成本都**不是**决定性因素；决定性的是规则和不能微调。

## 6. 建议

**优先级 1 — 修标签，这比接任何外部模型都重要。**
- 目标泄漏：把标签改成 `target_soft[i+1]`（真正的一步预测），或从 obs 移除 `sin/cos(yaw)`，
  或换成非闭式标签（例如下一秒是否对某敌造成伤害）。在 README 里把 oracle=1.000 与 0.7455 并列。
- 火力门时间错位：对齐到未来一秒，让两个 head 的时间锚点一致。

**优先级 2 — 唯一值得接入的用法：Jev 当火力门的离线教师。**
它在这一项 AUC 0.769 对 IQL 0.611、F1 0.525 对 0.381，且与泄漏无关。做法是离线标注 → KD 蒸馏进车上
的 MLP（走你们现成的 `export_policy.py` + `deploy.apply_safety`），比赛时不联网。
全量 25.7 万个对局秒按实测 8,683 tok/状态约 **94 美元**、1,200 RPM 下约 3.6 小时；
只做火力门可以去掉 113 个格子的 criteria，能压到约 5,000 tok / 54 美元。
**阈值必须按正类率定（约 0.23–0.29），不能用 0.5。**

**优先级 3 — 不要蒸馏 target 和 nav。** target 上 Jev 显著差于一行启发式；nav 上所有人都不如"不动"。
从比数据差的教师蒸馏是负迁移。

**优先级 4 — 真正的答案仍然是闭环仿真。** Jev 解决不了核心瓶颈。


```bash
PYTHONPATH=jev_demo python jev_demo/exp2_tactical.py --games 61 --n-jev 1200 --workers 14
```

以上命令在仓库根目录运行。前置条件：

- 数据集放在 `dataset/rmuc_2026_region_dataset.sqlite`，放在别处时用环境变量 `RMUC_DB` 指定路径；
- `data/vis_map.npz`、`data/team_prior.json` 与 `rm_runs/infantry_iql_tactical/` 已由 `scripts/run_all.sh` 生成；
- `pip install typesafe-sdk`（本次评估用 0.7.0），并在 `jev_demo/.env` 中写入 `TYPESAFE_API_KEY=...`。

`.env`、`sample.json`（真实对局状态切片）与原始 `.npz` 均被 `.gitignore` 排除，不随仓库分发；
`exp*_results.json` 是汇总统计，入库供核对本报告的数字。

**局限。**
- Jev 子样本 n=1,200 对 IQL 的 87,577，所以 Jev 的置信区间宽约 ±0.023。
- Jev 运行间存在约 ±0.01 的波动（两次全量跑：target 0.2150 / 0.2117，fire AUC 0.7593 / 0.7695）。
- 结果对 briefing 措辞敏感：70 token 摘要与完整 briefing 之间，同一状态的导航结论会 180° 反转。
  briefing 应当作超参数对待并验证，而不是写一版就上。
- 所有一致度指标以人类动作为标准答案，不构成对弈强度的度量（见 §4）。
